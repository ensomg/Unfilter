# Faz 7 Raporu

Çıktı formatı: master prompt §8. Kapsam: `uf-fallback` crate'i — DPI manipülasyonu
ve DNS düzeltmesinin çözemediği hedefler (gerçek IP seviyesi bloklar) için
*opsiyonel* tünel/proxy yolu. v1 = arayüz + soyutlama + tel kodlaması (wire codec)
hazır ve testli; canlı relay (soketi tutan, bayt kopyalayan döngü) v2'ye bırakıldı
ve kancaları (`Fallback`/`Handshake` trait'leri) tanımlı. Varsayılan KAPALI.

## 1. Tamamlanan iş paketleri ve kullanılan model

| İş paketi | Model | Durum |
|---|---|---|
| `Fallback` trait (hedefe bağlantı taşıyan upstream soyutlaması) | Opus | ✓ |
| `Handshake` saf durum makinesi (bayt-pompası, I/O'suz) | Opus | ✓ |
| SOCKS5 (RFC 1928) + user/pass (RFC 1929) tel kodlaması + handshake | Opus | ✓ |
| HTTP CONNECT istek/yanıt çerçeveleme + Basic auth (gömülü base64) | Opus | ✓ |
| WireGuard (userspace) arayüz + config — `wireguard` feature, `NotAvailable` yolu | Opus | ✓ |
| "IP-blocked" karar tipi (`TargetVerdict`) + yüklem (`should_use_fallback`) | Opus | ✓ |
| Config-as-data (`FallbackConfig`, serde; varsayılan `enabled=false`) | Opus | ✓ |
| `build_upstreams()` — config → sıralı canlı upstream listesi | Opus | ✓ |

Ağa çıkılmadı: tüm çerçeveleme saf bayt kodlaması/çözümlemesi olarak test edildi
(uf-dns'teki `Transport` deseni gibi). "Varsayılan yola sıfır gecikme" garantisi
kodda iki katmanlı: (1) `FallbackConfig::enabled` varsayılan `false`,
(2) `should_use_fallback(enabled, verdict)` yalnız `enabled && IpBlocked` için
`true` döner — normal/çözülebilir trafik fallback'i hiç görmez.

## 3. Açık riskler ve sapmalar

- **Canlı relay yok (v2):** `Handshake::pump()` saf durum makinesi; soketi tutan,
  byte kopyalayan asenkron relay döngüsü (tokio) serviste (Faz 6/8) yazılacak ve
  yalnızca `Fallback`/`Handshake` trait'lerini *sürecek* — bu crate'e tokio/async
  runtime girmedi (bilinçli; dağıtım bütçesi ve varsayılan yol temizliği için).
- **WireGuard userspace yalnız arayüz:** `wireguard` feature'ı ile derleniyor;
  `WireguardUpstream::connect` temiz tipli `NotAvailable` döner (panik yok). v2
  planı: userspace Noise IK el sıkışması (Curve25519/ChaCha20-Poly1305/BLAKE2s) +
  TUN'suz in-process encaps; kernel modülü/admin WG kurulumu yok (sıfır-config
  sözü korunur). Feature kapalı derlemede config `Wireguard` varyantı şemada
  durur ama `build_upstreams` onu atlar (hedef direkt kalır, hata değil).
- **Prober entegrasyonu (Faz 5):** `ProbeSummary::verdict()` ve `TargetVerdict`
  bu crate'te; prober bunları doldurup hedefi işaretleyecek. IP-blocked kararı
  sadece *hem* tüm DPI stratejileri *hem* DNS düzeltmesi başarısızsa veriliyor —
  son çare mantığı tek yerde (`ProbeSummary::verdict`).
- **Credential gizliliği:** `UserPass` düz metin serde alanı (config dosyasından
  gelir); loglara basılmaz (sadece upstream `kind` ve SOCKS/HTTP reply kodu
  loglanır). Profil şifreleme/kasa v1.1 kapsamı.
- **ATYP/port sırası:** SOCKS5 adres+port big-endian elle kodlandı; IPv4/IPv6/
  domain üçü de tablo testli. Domain >255 bayt ve user/pass >255 bayt encode'da
  `FieldTooLong` ile reddediliyor.
- `uf-core` değişmedi; `uf-fallback` yalnız `uf-core` + `serde`'ye (dev'de
  `serde_json`) bağlı.

## 4. Sonraki fazın başlangıç koşulları

- **Faz 5 (prober):** bir hedef için tüm DPI stratejileri + DNS düzeltmesi
  tükendiğinde `ProbeSummary` doldurup `verdict()==IpBlocked` ise
  `should_use_fallback` ile fallback'e yönlendirir. Yalnız o hedef (split tunnel).
- **Faz 6 (servis):** `build_upstreams(&config)` ile canlı upstream listesini
  kurar; IP-blocked akışın soketini açıp `connect(target)` → `Handshake::pump`
  döngüsüyle tünel kurar, sonra çift yönlü bayt relay yapar. HandshakeStep.send'i
  yazar, gelen baytı pump'a verir, `established` olunca relay'e geçer.
- **Faz 8:** fallback yolunun gecikme/throughput ölçümü (yalnız IP-blocked hedef;
  varsayılan yolun etkilenmediği ölçülecek) + WireGuard userspace handshake'i.
