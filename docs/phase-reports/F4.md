# Faz 4 Raporu — QUIC Initial ve SNI çıkarımı

Kapsam: QUIC istemci Initial paketinin genel başlığını okuma ve (ring ile)
ClientHello'dan SNI çıkarma. QUIC yalnızca *okunur*; asla üretilmez/enjekte
edilmez.

## 1. Tamamlanan iş paketleri ve kullanılan model

| İş paketi | Model | Durum |
|---|---|---|
| Uzun-başlık Initial genel ayrıştırma (v1 + v2), coalesced | Opus 4.8 | ✓ |
| Initial anahtar türetme (HKDF-Expand-Label), DCID'den | Opus 4.8 | ✓ |
| Başlık koruması kaldırma + AES-128-GCM yük çözme (ring) | Opus 4.8 | ✓ |
| CRYPTO akışı birleştirme → TLS handshake | Opus 4.8 | ✓ |
| `extract_sni`: uçtan uca (uf-core TLS parser'ı yeniden kullanır) | Opus 4.8 | ✓ |

## 2. Kabul kriteri ölçüm sonuçları

| Kriter | Sonuç |

## 3. Açık riskler ve sapmalar

- **v2 kısmen vektörsüz:** v1 RFC 9001 vektörleriyle bire bir doğrulandı. v2
  (RFC 9369) salt ve `quicv2 *` etiketleriyle uygulandı; RFC 9369 vektörü
  eklenmedi — v2 yapısal olarak doğru, ama v1 kadar sıkı doğrulanmadı.
- **Yalnız istemci Initial:** sunucu anahtarları ve 0-RTT/Handshake seviyeleri
  türetilmez (SNI için gereksiz).
- **Çok-datagram ClientHello:** tek datagramda tamamlanmayan (parçalı) bir
  ClientHello `Truncated` döner; birden çok Initial datagram boyunca yeniden
  birleştirme v1.1 kapsamı.
- **Motor entegrasyonu:** `extract_sni` kütüphane olarak hazır; servisin UDP/443
  akışlarında bunu çağırıp QUIC bypass stratejisi uygulaması ayrı iş (TCP desync
  F2'de). `decrypt` feature'ı kapatılırsa yalnız genel ayrıştırıcı derlenir.

## 4. Sonraki fazın başlangıç koşulları

- Servis UDP/443 ilk datagramında `uf_quic::extract_sni` ile hedefi tanır;
  QUIC desync (sahte Initial / UDP bölme) motoruna eklenir.
- v2 için RFC 9369 test vektörü eklenebilir.
